Picking a place that builds

Your two asks, verbatim: “Once a place is shown while typing in the place textbox, it should be guaranteed to render on the map.” And: “You mentioned that there are multiple views of Kolkata, this is causing confusion — have a mechanism to resolve this from the beginning.” They are one moment in the product, so this is one page. Every outline below is the real boundary from the same cached files the product searches; every quoted string is verbatim from the live code.

I would ship — one rule in three parts 1. The list offers only ground the builder can honour — for India today that is states and districts, so “kolkata” returns one row, not three. 2. A name shared by several grounds becomes one row that opens into drawn choices: real outline, real size, plain words (seven Indian district names are shared today). 3. The row says what it will produce before any wait — and if a build still dies, it leaves a working “Try again”, not a dead button and a burnt name.
The finding that reframes the question The row labelled “district” was the smallest of the three Kolkatas — 91 km² against the official district’s 185. The level words under the rows are admitted guesses in the code, and here they invert the truth. Worse: after the threshold fix, all three rows build nearly the same district atlas anyway. A choice that can kill the build but cannot meaningfully change it should not be a choice at all.

2 · The three Kolkatas, drawn for real

The actual boundaries behind the three rows, at one shared scale, each laid over the official district (dashed moss) that every India build must match. The words said district > subdistrict > locality. The ground says the opposite.

the row’s real boundary the official Kolkata district — 185 km²

And after the threshold fix — all three rows lead to the same ground

The India boundary builder never reads which level was picked: it lays the pick over the official district list and the matching districts become the atlas. All three Kolkata rows match the same one district, so all three build the same boundary layer, the same map frame, the same key facts — only the crop of the picture layers (satellite views, land-use images) differs a little. Four rows offered, one meaningful outcome, one of the four fatal before the fix. That is why the mechanism below removes the fake choice rather than explaining it.

3 · The rule, weighed

Three candidate rules for “nothing offered that cannot build”. The differences are when the person learns and what they are left holding.

Offer everything, explain each rowCheck the moment a row is pickedOffer only what builds — checked when the list is made
When you learn After reading — and the words can lie (§2: “district” was the smallest shape). At pick time — a second’s pause while the builder’s own match runs ahead of the wait. Never — an unbuildable row simply never appears.
What you hold A four-way choice with one meaningful outcome — the fake choice survives, now with more words. A refusal after you have already chosen — “you can’t have what we offered”. Only real choices. “kolkata” becomes one row.
What it costs Longer rows, no engineering. One check per pick against the official list — quick (a warm build is under 5 s), but paid on every pick, forever. A small table per country of what each builder honours, kept next to the builders; India’s says “states, districts” today and grows when the builders do.

Shipped rule: the third, with the second as its safety net. The list is generated from the builder’s own reach, so the guarantee is structural, not checked per pick. The pick-time check remains only as a backstop for the day a source moves — and when it fires, it refuses in the box, in words, before any wait.

4 · The box, redrawn — both asks answered in one drawing

True size. One row per place. The ground is drawn, sized, and checked before the person can start a build. Where one name means several grounds, the row opens into drawn choices — outline and size, not level words. Seven Indian district names need this today: Bilaspur, Hamirpur, Aurangabad, Balrampur, Bijapur, Raigarh, Pratapgarh — all measured from the real files.

The mechanism, general: one row per name; where the name is honestly several grounds, the grounds are drawn side by side at true relative scale — a 3× size difference is visible in a way “district · Mahārāshtra” never was. The same drawing carries any future case: when India’s builders learn blocks, “Kolkata — the whole district” and “one part of it” sit here as two drawn choices, sized, both guaranteed, because neither is offered until it builds.

When a build still dies — the back half of the guarantee
A source can still move after the list was made. Then: the message stays in plain words, “Try again” works without reloading, and the atlas’s name is released instead of a “Not live” husk holding it. Today all three are missing (§1, step 5).
Try again the name “Kolkata Commons” is yours again
